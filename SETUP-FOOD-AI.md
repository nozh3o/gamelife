# Распознавание еды по фото — настройка

Приложение умеет оценивать КБЖУ по фотографии тарелки. Запрос идёт не напрямую из
браузера, а через маленькую функцию в твоём проекте Supabase — **ключ от сервиса
распознавания хранится там и в браузер никогда не попадает.** Иначе его смог бы
достать любой, кто откроет сайт.

Настройка разовая, минут на десять. Supabase и CLI ставить не нужно — всё делается
в веб-консоли.

---

## Что понадобится

- Проект Supabase (тот же, что для синхронизации).
- Доступ к сервису с распознаванием картинок и ключ от него.

---

## Шаг 1. Создать функцию

1. В проекте Supabase открой раздел **Edge Functions**.
2. Нажми **Deploy a new function** → **Via Editor**.
3. Имя функции — ровно `analyze-food`.
4. Удали содержимое редактора и вставь весь код из файла
   [`supabase/functions/analyze-food/index.ts`](supabase/functions/analyze-food/index.ts).
5. Нажми **Deploy**.

## Шаг 2. Прописать секреты

В **Edge Functions → Secrets** (или Project Settings → Edge Functions) добавь:

| Имя | Значение |
|---|---|
| `FOOD_API_URL` | Базовый адрес сервиса, например `https://api.твой-сервис.com/v1` |
| `FOOD_API_KEY` | Твой ключ |
| `FOOD_API_FORMAT` | `anthropic` или `openai` — смотря какой формат у сервиса |
| `FOOD_MODEL` | Идентификатор модели, например `claude-opus-5` |

**Как понять формат.** Посмотри документацию своего сервиса:

- если в примерах есть `/v1/messages` и заголовок `x-api-key` — это `anthropic`;
- если `/v1/chat/completions` и `Authorization: Bearer` — это `openai`.

Многие посредники поддерживают оба формата. Если не угадал — просто поменяй значение
секрета и попробуй снова, перевыкладывать функцию не нужно.

В `FOOD_API_URL` указывай адрес **без** `/messages` и `/chat/completions` на конце —
функция допишет нужный путь сама.

## Шаг 3. Связать с приложением

1. В Supabase скопируй адрес функции — он выглядит как
   `https://ТВОЙ-ПРОЕКТ.supabase.co/functions/v1/analyze-food`.
2. В приложении: **Настройки → Синхронизация → Распознавание еды по фото** — вставь адрес
   и нажми «Сохранить адрес».
3. Готово. На вкладке **Питание** кнопка «📷 По фото» станет рабочей.

Важно: сначала нужно войти в аккаунт синхронизации — функция принимает запросы только
от авторизованных пользователей твоего проекта, чтобы её не мог дёргать посторонний.

---

## Как это работает

1. Телефон сжимает снимок до 1024 пикселей по длинной стороне — так быстрее и дешевле.
2. Картинка уходит в твою функцию вместе с токеном твоей учётки Supabase.
3. Функция подставляет ключ из секретов и обращается к сервису распознавания.
4. Обратно приходит название блюда, примерный вес порции и КБЖУ.
5. **Приложение показывает форму с этими значениями — ты правишь и сохраняешь.**

Последний пункт принципиален. Оценка по фотографии всегда приблизительная: размер порции
без масштаба определить трудно, а масло, сахар и заправки на снимке не видны. Сильнее всего
на цифры влияет вес порции — если знаешь его, поправь, и остальное станет заметно точнее.

## Если что-то не работает

| Что видишь | Что проверить |
|---|---|
| «на сервере не заданы FOOD_API_URL или FOOD_API_KEY» | Секреты не сохранились или названы иначе |
| «сервис распознавания ответил 401» | Неверный ключ |
| «сервис распознавания ответил 404» | Неверный `FOOD_API_URL` или не тот `FOOD_API_FORMAT` |
| «модель вернула не JSON» | Модель не поддерживает картинки — проверь `FOOD_MODEL` |
| «не авторизован» | Не выполнен вход в аккаунт синхронизации в приложении |

Подробности ошибок видны в Supabase: **Edge Functions → analyze-food → Logs**.

## Бесплатные альтернативы

Распознавание по фото — не единственный путь, и не самый точный:

- **📦 Штрихкод** — берёт точные цифры с упаковки из открытой базы Open Food Facts.
  Бесплатно, без ключей, фото никуда не уходит. Лучший вариант для магазинных продуктов.
- **📖 Мои блюда** — личный словарь: один раз ввёл, дальше добавляешь в один тап.
  Через пару недель закрывает большую часть повседневной еды.
- **🔍 Найти продукт** — поиск по той же открытой базе по названию.

Всё это работает без всякой настройки и без затрат.
